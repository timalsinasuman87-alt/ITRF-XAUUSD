# ITRF v0.10.1 Purged Event-Research Specification

## Purpose

Version 0.10.1 tests the research framework, not a deployable strategy. It asks
whether a fixed causal context feature family improves chronological probability
estimates beyond simpler benchmarks on the already inspected v0.10 event set.

This specification is frozen before inspecting v0.10.1 model results. No model
probability is converted into a trade-entry threshold.

## Event universe and target

- Target instrument: XAU/USD only
- Events: the 212 `ACCEPTED` one-position-at-a-time events produced by the
  frozen v0.10 clean core
- Feature time: completed signal-bar close
- Entry and outcome: unchanged v0.10 next-open, 1R stop, 3R target, 32-bar
  timeout
- Binary research target: 1 only when the 3R target terminates the event;
  stop and timeout are 0
- Continuous diagnostic: realized gross R from the clean core
- Same-bar ambiguity: events with unequal lower and upper R bounds are retained
  in the ledger but excluded from binary model fitting

The event universe, outcomes, and position sequencing may not change after
model results are inspected.

## Fixed feature families

### Price/activity baseline

1. Direction indicator
2. Trend alignment with event direction
3. Direction-signed five-bar ATR momentum
4. Direction-signed v0.8 delta-proxy z-score
5. Relative tick activity
6. v0.8 high-volatility flag

### Causal context expansion

The baseline plus:

1. EMA market-regime alignment
2. Confirmed swing-structure bias alignment
3. Directional liquidity sweep on the signal bar
4. Premium/discount location aligned with direction
5. Directional BOS or CHoCH event on the signal bar
6. Directional displacement on the signal bar
7. Direction-signed distance from close to the confirmed dealing-range midpoint,
   normalized by ATR

All features must exist at the signal-bar close. Confirmed pivots remain delayed
by the causal swing-confirmation window.

## Fixed models

1. `constant_null`: training-fold target frequency
2. `price_activity`: L2-regularized logistic regression using the fixed baseline
3. `causal_context`: the same model using the fixed expanded feature set

The logistic implementation uses training-only median imputation and
standardization, an unpenalized intercept, fixed L2 strength 1.0, and no
hyperparameter search.

## Chronological evaluation

- Three expanding walk-forward test folds
- Initial test begins after 40% of chronological events
- Remaining 60% is divided into three consecutive test folds
- Training uses past events only
- A training event is retained only when its outcome interval ends at least 32
  source bars before the test fold begins
- Test events are never shuffled
- All preprocessing is fitted on each training fold only

This 32-bar pre-test embargo is deliberately conservative. Fold integrity must
be proven by tests using source-bar signal and exit indices.

## Metrics

- Brier score
- Log loss
- ROC AUC when both test classes exist
- Mean predicted success probability
- Observed success frequency
- Paired circular block-bootstrap 95% interval for Brier improvement versus
  `constant_null`

Positive Brier improvement means lower squared probability error than the null.
Calibration and discrimination must both be considered; one attractive fold is
not sufficient evidence.

## Decision rule

This inspected dataset cannot promote an edge. The only possible conclusions
are:

- framework functions and context is promising enough to pre-register on new
  untouched data, or
- context adds no stable information and should be revised or rejected.

No direction, feature subset, probability cutoff, model coefficient, time
window, or profitable fold may be selected from the results.
