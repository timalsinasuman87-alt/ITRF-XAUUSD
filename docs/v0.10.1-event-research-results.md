# ITRF v0.10.1 Purged Event-Research Results

## Status

The pre-registered v0.10.1 comparison has been completed on the already
inspected XAU/USD development sample. It is a framework diagnostic, not an
out-of-sample validation, a profitability claim, or a deployable strategy.

The specification was committed before model results were inspected. No
feature family, coefficient, probability cutoff, direction, fold, or trading
rule was selected after seeing the results. No new data was downloaded, no live
feed or order path was used, and the incremental cost was $0.

## Pooled walk-forward probability metrics

| Fixed model | Brier score | Log loss | ROC AUC | Mean probability | Observed success |
| --- | ---: | ---: | ---: | ---: | ---: |
| Training-frequency null | 0.1169 | 0.3981 | 0.4740 | 0.1740 | 0.1328 |
| Price/activity baseline | 0.1185 | 0.4021 | 0.6100 | 0.1480 | 0.1328 |
| Expanded causal context | 0.1214 | 0.4067 | 0.6433 | 0.1542 | 0.1328 |

Lower Brier score and log loss are better. The expanded context had the best
pooled ranking statistic, but both fitted models produced worse probability
errors than the simple training-frequency null. Better ranking alone is not a
usable or calibrated edge.

## Stability across folds

| Fold | Null Brier | Price/activity Brier | Causal-context Brier |
| --- | ---: | ---: | ---: |
| 1 | 0.1515 | 0.1632 | 0.1663 |
| 2 | 0.0924 | 0.0846 | 0.0817 |
| 3 | 0.1066 | 0.1075 | 0.1160 |

The expanded model improved in fold 2 but degraded in folds 1 and 3. Selecting
the attractive middle fold would be post-result cherry-picking.

| Model versus null | Mean paired Brier improvement | Circular block-bootstrap 95% interval |
| --- | ---: | ---: |
| Price/activity | -0.00162 | [-0.01429, 0.00900] |
| Expanded causal context | -0.00445 | [-0.02205, 0.01442] |

Positive improvement was defined in advance as lower error than the null. Both
means are negative and both intervals cross zero, so this sample does not show
stable incremental probability information.

## Numerical integrity correction

An initial development replay exposed a platform-specific floating-point
warning in the small logistic solver. Those preliminary numbers were rejected.
The implementation was replaced with deterministic, bounded-gradient updates,
a near-separation stress test and an end-to-end finite-prediction test were
added, and the warning-sensitive replay was rerun before the results above were
accepted.

## Decision

The current same-decision-time causal-context feature family is **not promoted
as an edge**. It may contain weak ranking information, but it did not improve
calibrated chronological probabilities beyond the null and was not stable
across folds. No probability threshold or trade filter should be derived from
this development sample.

## Next research increment

Do not tune the logistic model or search feature subsets. The next increment
should be a pre-registered failure-anatomy study over the clean event ledger:

1. Measure when stops, targets and timeouts occur across the 32-bar lifecycle.
2. Measure causal pre-entry setup age and state transitions separately from
   same-bar flags.
3. Report competing event hazards and MFE/MAE distributions without converting
   them into entry rules.
4. Use those diagnostics to state one new economic mechanism before testing it
   on an untouched period.

This separates understanding why the engine fails from searching the same data
for a profitable rule.
