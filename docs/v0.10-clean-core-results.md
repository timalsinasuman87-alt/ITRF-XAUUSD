# ITRF v0.10 Clean Core Results

## Status

The frozen v0.8 entry signal was replayed through the pre-registered v0.10
event-driven core. This is an architectural validation on already inspected
development data. It is not an out-of-sample test or profitability claim.

No parameter, direction, time window, regime, stop, target, or holding period
was selected after viewing these results. No new data was downloaded, no live
feed was connected, and the incremental cost was $0.

## Integrity correction during implementation

The first implementation replay allowed a few dataset-end candidates with less
than the full 32-bar horizon. That right-censoring was detected before final
reporting. The ledger now explicitly classifies such candidates as
`REJECTED_INCOMPLETE_HORIZON`, and a regression test prevents their acceptance.
The corrected results below supersede that development run.

## Candidate ledger

| Decision | Count |
| --- | ---: |
| Accepted sequential trade | 212 |
| Rejected because a position was open | 173 |
| Rejected because the 32-bar horizon was incomplete | 3 |

The 212 accepted trades exceed the v0.8 audit's 107 mechanically
non-overlapping fixed-window observations because the clean event engine frees
the position when a real stop or target occurs, often before 32 bars. It does
not permit simultaneous positions.

stop-first and upper target-first outcome bounds are identical. The engine
still preserves both bounds for other samples.

## Architectural result

Version 0.10 successfully separates:

- completed-bar signal time from next-open entry time
- candidate decisions from accepted sequential positions
- price events from aggregate reporting
- known stop/target order from unknowable intrabar order
- gross outcome from cost sensitivity
- full-horizon trades from right-censored candidates

This clean core is suitable for testing new hypotheses. The v0.8 score is not.

## Next research increment

The next hypothesis should not add more points to the v0.8 score. It should
build a causal event dataset and measure whether explicit context variables add
information beyond a price-only benchmark:

1. Market-regime state known before the setup
2. Confirmed swing structure and BOS/CHoCH event time
3. Liquidity-sweep arm, invalidation, replacement, and expiry
4. Premium/discount location relative to a causal dealing range
5. Post-sweep displacement/confirmation
6. Historical order-flow context only as a separately tested feature family

Mathematical evaluation should use chronological, purged walk-forward folds
with at least a 32-bar embargo, retain rejected events, report calibration and
confidence intervals, and compare against simple null models. The framework
must be implemented before choosing any model or feature threshold.
